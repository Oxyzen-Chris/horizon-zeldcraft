Préparer les données pour futur widget Plateforme 3D :
Expliques moi ce que tu as fait sur la partie "Préparer les données pour futur widget Plateforme 3D" et comment l'utiliser pour la création de ce nouveau widget 3D ? :

Maintenant je vois l'ensemble du contexte. Je vais expliquer comment on prépare le jeu pour passer d'une isométrie 2D plate à une future architecture 3D sans tout reconstruire, en détaillant les modifications concrètes apportées à l'interface `Tile` avec les nouveaux champs optionnels pour l'altitude et la profondeur. hauteur Y du mesh de terrain, `depthM` pour la profondeur du fond marin/lac, `waterKind` pour les matériaux et textures d'eau selon le type, et `isIsland` pour gérer les rives et plages visuellement. Les mêmes règles de gameplay (altitude, raréfaction, eau) s'appliquent sans duplication — seul le rendu change de 2D isométrique à 3D — donc il suffit d'écrire un nouveau composant WebGL/Three.js qui consomme les données `Tile` et les convertit en géométrie, la couche données étant déjà prête. Les valeurs sont bornées à ALTITUDE_MAX_M=6000 et WATER_DEPTH_MAX_M=6000.

Voici ce qui a été préparé pour le futur widget "Plateforme 3D", et comment vous en servir le moment venu :

Ce qui a été fait (fichier  web/src/lib/worldTerrain.ts )

L'interface  Tile  (renvoyée par  worldTileAt(wc, wr, poiPoints) , LA fonction unique qui calcule le terrain d'une case — déjà utilisée par  GameCanvas2D.tsx  et  WorldMapWidget.tsx ) a été enrichie de champs optionnels :

•  altitudeM  (dalles  rock  uniquement) — relief en mètres, jusqu'à 6000 m ( ALTITUDE_MAX_M ), calculé par chaîne de montagnes via le rayon du POI  mountain / cave .
•  depthM  (dalles  water  uniquement) — profondeur immergée en mètres, jusqu'à 6000 m ( WATER_DEPTH_MAX_M ), variable selon le type (ruisseau ~3m, étang ~6m, lac ~45m, mer ~260m, océan jusqu'à 6000m).
•  waterKind  —  'stream'|'pond'|'lake'|'sea'|'ocean' , pour distinguer le type de plan d'eau.
•  isIsland  — case appartenant à une île.

Tout est déterministe (même hash PRNG que le reste du décor : mêmes coordonnées = mêmes valeurs à chaque appel) et optionnel ( undefined  si non pertinent), donc zéro régression : le code existant qui ignore ces champs continue de fonctionner à l'identique.

Déjà exploité en 2D aujourd'hui
Raréfaction de l'air (oxygène/fatigue) selon altitude/profondeur ( computeRarefactionFactor()  dans  GameCanvas2D.tsx ), neige en haute altitude, tooltip "250 m"/"−12 m", blocage d'accès aux îles sans engin.

Comment l'utiliser pour créer le widget 3D

1. Réutiliser tel quel  worldTileAt()  comme source de vérité du terrain (aucune nouvelle logique de génération à écrire).
2. Mapper directement dans le moteur 3D (ex. Three.js) :  altitudeM  → hauteur Y du relief émergé,  depthM  → creux du fond sous le niveau de la mer,  waterKind  → texture/couleur/matériau de l'eau,  isIsland  → gestion des rives/plages.
3. Réutiliser les mêmes  RepRules  (oxygène, fatigue, raréfaction) sans dupliquer le gameplay — seul le rendu change.

Il ne restera donc qu'à écrire le composant de rendu 3D lui-même ; la couche données est déjà prête.
